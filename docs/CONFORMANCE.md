# Conformance plan

Status: this is the acceptance plan for a library that does not exist yet. No property below has been implemented or run. Wherever this document says "must", it states a release requirement for the first release. Defect classes are taken from a single NeoGraph audit and from surveys of other projects (see `RESEARCH.md`). They are observations, not incidence rates.

## 1. Purpose

The suite answers one question: does the library hand its caller the same messages, tool calls, usage, stop reason and failure that the vendor's protocol actually means? It does not measure code coverage or test count.

Design target: request, then a validated immutable plan, then one transport attempt, then a family frame decoder, then semantic events, then one accumulator, then a `Completion` or a `Failure`. Non-stream, SSE and WebSocket share the event and accumulator path. The suite is organised around that path and around the failure classes that previously broke tool loops, usage accounting and reasoning replay.

### 1.1 Oracle philosophy

No single kind of evidence is trusted as truth. A property passes only with an oracle that does not share code with the thing tested.

| Oracle | What it is | What it catches | Limit |
|---|---|---|---|
| Reviewed golden | A hand-reviewed expected result for a recorded or synthetic exchange. A person wrote or approved the expected events, completion, usage and stop from the vendor documentation and the wire bytes. | Wrong mapping of a real vendor response | Only as good as the review. Never generated by the production decoder. |
| Reference state machine | A tiny independent implementation of the event lifecycle, written in test code with its own tables. | Illegal orderings, double outcomes, events after terminal, wrong tool ownership across many generated sequences | Must not share helpers or tables with production. |
| Metamorphic relation | A transformation of the input that provably preserves meaning for that fixture (byte re-partition, comment lines, line-ending variants, legal interleaving). Output must be equal. | Framing bugs, state kept per read instead of per stream | Only relations proven safe for the specific fixture are applied. |
| Real loopback transport | The real client talking to a scripted local HTTP, SSE or WebSocket server that reports the requests it received, resets connections and delays reads. | Socket-path bugs, cancellation, early EOF, lifetime races, request shape on the wire | Not a vendor. It proves the client, not the vendor. |
| Same-origin live canary | A small real two-turn tool loop against the real vendor, using exactly what the first turn returned. | Wire drift, replay acceptance, signature binding, real usage arithmetic | Non-deterministic prose. Structural assertions only. Costs money. |

Differential comparison of two live models is not an oracle, because their answers legitimately differ. Comparing the old and new implementation on the same recorded input is an investigation tool for the migration gate (section 10), not an oracle: it confirms nothing about which side is right.

Rules that keep the oracles honest:

- Expected values are never produced by running the production decoder and approving the output. Fixtures changed by a pull request and their expected projections must not be approved together by one reviewer without a second reviewer.
- A failing characterization of an old bug is never frozen as golden. Only consumer-visible meaning that a reviewer can justify stays.
- Normalization in the comparison must not erase differences that matter (absent versus zero, empty versus missing, which block owns a signature).
- Agreement of several independent implementations is not proof, because they can share one misreading of the spec.

### 1.2 Why server-side Open Responses compliance is not enough

The Open Responses suite tests a server. A client library decodes and assembles what servers send, so the suite cannot test our code. Further facts from the survey:

- It needs a live Responses-compatible server, a real model and an API key. It has no mock or deterministic mode. Its prompts are fixed short free-text requests and most verdicts are "schema valid and not empty".
- It contains no reasoning assertions, no reasoning round trip, no stream-assembly check (argument fragments, ordering, accumulated text equals final text), no usage-value check, no handling of EOF without a terminal event, and its tool-calling case is non-stream.
- Its own SSE parser has reported defects (multiple `data` lines overwritten, last event lost). The survey's reading that an event split across network reads can be dropped is an inference from code and was not run.
- Its schema is reported as tied to one vendor's shape, and the specification leaves replay of opaque reasoning across providers undefined.

What is reused from it: the published schema can validate fixtures, and the suite can be run against real vendors to capture traffic that we then review. Passing it is never listed as evidence for a release gate here.

### 1.3 Record and replay pitfall

Common recorders match on method, scheme, host, port, path and query by default, and leave the body and headers out. Two requests to the same `POST /v1/messages` with different model, tools, reasoning settings or beta headers then match the same recording. A payload regression passes green. One surveyed framework documents this weakness in its own test guide.

Countermeasures, all mandatory in the fixture runner:

- The matcher compares method, authority and path, the semantic headers named in the fixture, and the request body (structural JSON equality after scrubbing, with opaque strings compared exactly).
- A recorded interaction that is never consumed fails the test. An unrecorded request fails the test. Repeat-playback is off unless a fixture declares `request_count`.
- Automatic re-recording and TTL-based overwrite are not allowed to change a golden. New captures go to a review artifact.

Consumer-driven contract testing (Pact) is also not adopted as a vendor guarantee. The vendors do not run our contract, so a green broker says nothing about them. It would be meaningful only at the boundary to a gateway that both sides control.

## 2. Fixture format

One JSON file per scenario. Large binary bodies go to a sidecar file referenced by content hash. No YAML, no runtime recorder, no manifest/request/wire/expected four-file split unless a case needs it.

```json
{
  "fixture_version": 1,
  "case_id": "messages-tool-loop-signed-thinking",
  "origin": {"family": "anthropic.messages", "vendor": "anthropic", "authority": "direct"},
  "descriptor_digest": "sha256:...",
  "provenance": {
    "kind": "synthetic | captured",
    "api_version": "...", "model": "...", "captured_at": "...",
    "doc_reference": "vendor documentation page title",
    "reviewer": "...", "review_date": "..."
  },
  "request": {
    "method": "POST", "path": "/v1/messages",
    "semantic_headers": {"anthropic-version": "...", "anthropic-beta": "..."},
    "body": {}
  },
  "transport": {
    "mode": "buffered | sse | ws",
    "status": 200, "headers": {},
    "schedule": [
      {"kind": "bytes", "utf8": "event: message_start\r\n"},
      {"kind": "bytes", "sidecar": "case.001.bin", "sha256": "..."},
      {"kind": "delay_ms", "value": 25},
      {"kind": "ws_message", "text": "...", "fragmented": false},
      {"kind": "reset"},
      {"kind": "eof"}
    ]
  },
  "expect": {
    "request_count": 1,
    "events": [{"type": "Begin"}, {"type": "PartDelta", "...": "..."}],
    "outcome": "completion | failure",
    "completion": {"messages": [], "usage": {}, "stop": "tool_use"},
    "failure": {"class": "...", "retry_advice": "...", "attempt_evidence": "..."}
  },
  "scrub": {
    "version": 1,
    "id_replacements": {"toolu_01": "call_A"},
    "removed_fields": ["authorization", "account_id"],
    "replay_eligible": false,
    "log": ["..."]
  }
}
```

Field rules:

- `provenance`: `synthetic` fixtures cite the documentation they were written from. `captured` fixtures record the real API version, model and date. A reviewer name and date are required for both. Content digests tie the file to its sidecars. The digest is an integrity check and is never treated as proof of meaning.
- `request`: the complete outbound request to match, after scrubbing. `semantic_headers` lists only headers that change vendor behaviour (API version, beta flags, content type, accept). Authorization and other credentials are never part of a fixture.
- `transport.schedule`: the scripted bytes or messages. This is a separate layer from the semantic expectation: it fixes chunk boundaries, delays, WebSocket fragmentation, connection reset and EOF. Metamorphic variants rewrite the schedule, not the semantic case. A JSON-reassembled response alone is not a streaming test.
- `expect.events`: the reviewed semantic event projection using the closed ten-event vocabulary (`Begin`, `MessageBegin`, `PartBegin`, `PartDelta`, `PartSeal`, `MessageSeal`, `UsageUpdate`, `Stop`, `Commit`, `Fail`). Chunk boundaries, local ids, timestamps, request ids and loss diagnostics are not part of the projection.
- `expect.outcome`: exactly one of a completion or a failure. A truncated exchange expects a failure. A scrub that removes the terminal event to "tidy" a fixture is forbidden, because it hides truncation.
- `scrub`: a log of every transformation applied. `replay_eligible: false` marks fixtures whose signatures or encrypted reasoning were replaced, which means they verify parsing and assembly but are no evidence that a vendor would accept the replay.
- Sidecars: any body that is large, binary or not valid UTF-8, referenced by relative name and SHA-256.

Directory discovery loads all fixtures and runs them across the properties that apply. Adding a vendor fixture needs no test wiring code.

## 3. Scrubbing rules

Fixtures become public. Scrubbing runs on capture and is re-checked in CI.

| Material | Rule |
|---|---|
| API keys, bearer tokens, cookies, signed URLs, query secrets | Removed. A scanner fails the build on any key-shaped string or authorization header in fixtures, logs and test output. |
| Account, organisation, user and workspace identifiers; request ids | Replaced by stable placeholders. The same real id always maps to the same placeholder so that correlation (tool call id to tool result) survives. The vendor error bodies that embed account or user identifiers are scrubbed before storage. |
| Prompt text and tool values | Replaced by public synthetic values. Real user data is never stored. |
| Signed or encrypted reasoning, redacted blocks, opaque vendor state | Never published as captured. A public fixture carries a synthetic capsule with the same structure and is marked `replay_eligible: false`. Real opaque bytes used for live replay tests are restricted, held only for the test run and deleted. Regex scrubbing cannot make ciphertext public-safe. |
| Generated response ids | Consistent substitution. The substitution map is recorded in the scrub log. |
| Timing | Captured timing is replaced by the scripted delays in the schedule. |
| Terminal and error events | Never removed to shorten a fixture. |

Reasoning bytes are treated as secret-bearing state in logs, exceptions and telemetry. A test plants a marker in a synthetic capsule and asserts it appears in none of the log, exception text or public fixture output, and only in an explicitly allowed sensitive export.

## 4. Support matrix rule

The support matrix is a table of cells: family, vendor descriptor, transport (buffered, SSE, WebSocket), and feature (text, tool loop, reasoning replay, cache, structured output, optional knobs).

- A cell is `Supported` only if every property that applies to it passed with its fault injection observed (section 5). Otherwise it is `Unsupported` (the request is rejected with an explicit error) or `Unverified` (documented as such). There is no fourth state.
- Skipped or not-applicable tests are never counted as passes. The report prints three totals (supported, unsupported, unverified) and lists every skip with its reason.
- A property with zero applicable cells in a family must carry an explicit, reviewed "not applicable" reason. For example, WebSocket applies to the Responses family only.
- A cell whose live canary has not run is `Unverified` for replay acceptance, whatever the recorded fixtures say.
- The support table in the documentation is generated from descriptors plus evidence dates. CI fails if the documentation claims a cell that has no evidence.

## 5. The 14 MUST properties

General rules for every property:

- Each property declares the fault it injects. The harness records that the fault actually fired (a counter that must be at least one) and fails the test if it did not, so a property cannot pass because the trigger never ran.
- For every property, a deliberately broken variant of the decoder, accumulator or client (a mutant kept in a test-only build) must fail it. If a mutant passes, the property is vacuous and is itself a release blocker.
- Every property runs over every supported cell where it applies, including buffered, SSE and WebSocket paths.
- "Defect class prevented" cites what was observed in the NeoGraph audit (issue and PR numbers of that repository) or in the surveyed projects. The survey's issue numbers belong to those projects.

### 5.1 ChunkPartitionInvariant

- Statement: for any partition of the same byte stream, including splits inside a UTF-8 sequence, between CR and LF, inside a BOM, inside a multi-line `data` value and at event delimiters, framing yields identical frames and the final completion or failure projection is identical. An event without its terminating blank line at EOF is never dispatched.
- Exercised by: metamorphic relation over every fixture. Exhaustive single-split sweep for fixtures up to a size cap, and seeded random multi-way partitions above it. Expected frames for the framing corpus are written from the SSE specification, not from our framer.
- Fault injected: partitions that hit each boundary class (multibyte character, CR/LF pair, BOM, between `data:` lines, blank-line delimiter, before final blank line). A coverage assertion checks that each class was hit. A mutant framer that resets state per read must fail.
- Prevents: events dropped when a delimiter straddles two reads, and loss of the last event or overwrite of multi-line data. Reported for another project's SSE parser (issue 56 of that project); multi-line `data` and trailing-event defects are the class.

### 5.2 NoTerminalNoSuccess (includes ExactlyOneOutcome)

- Statement: no EOF, clean close, reset, in-band error event, HTTP 200 with an error body, failed Responses status or early WebSocket close produces a successful completion. Terminal evidence is what the family defines as terminal. Empty output without terminal evidence is a failure. When terminal, error and cancel race, the caller gets exactly one outcome and no callback fires after it.
- Exercised by: reviewed golden for each termination shape, reference-machine runs over generated sequences, real loopback server that closes early, and a cancel and deadline race harness.
- Fault injected: cut the stream before each possible terminal event; send `200` plus error body; send an error event after text; close WebSocket early; fire cancel and terminal in the same scheduling turn.
- Prevents: stream cut without terminal reported as a normal `end_turn` (NeoGraph audit, issue 307); error events ignored by the stream parser; non-stream `failed` status or Gemini block reasons becoming quiet `end_turn`; OpenRouter upstream failures returned as HTTP 200 with an error body. In other projects: EOF synthesized as a stop (LiteLLM), truncated stream ending as 200 with no signal (Portkey, issue 1797), a stream error swallowed into `stop` (LiteLLM, issue 23707).

### 5.3 KnownCorruptNeverIgnored

- Statement: frames are Known, Unknown or Corrupt. A known tag with a wrongly typed or missing required field is Corrupt and fails the operation. An unknown event that cannot be shown harmless is not silently skipped and never produces a success on its own. Only known-harmless extensions and explicitly optional unknown fields are skipped, by family rule.
- Exercised by: discriminator matrix per family (known-valid, known-malformed, unknown-harmless, unknown-critical) with reviewed expected outcomes. Both directions are tested.
- Fault injected: for each known tag, break one required field; add an unknown optional field to each event; add an unknown event type. Mutants: one that ignores every unknown event, and one that rejects every unknown field.
- Prevents: the "undeclared event is skipped" default that hid error events (NeoGraph audit, issue 307). The opposite defect is also guarded: a strict typed reader that rejects a valid response because a vendor added a field or sent two alias fields (BAML alias defect; closed-enum failures in async-openai and rig).

### 5.4 InterleavedToolOwnership

- Statement: with legally interleaved tool calls, each call keeps its own id, name, arguments and signature. Partial argument text is never an executable call. A call becomes executable only when sealed. An explicit empty object `{}` is distinguished from missing arguments. Text after a close or stray argument deltas after the response ended cannot corrupt a sealed call.
- Exercised by: reviewed golden per id, reference state machine over generated legal interleavings (per-call order preserved), property generator with a shrinker that keeps id dependencies.
- Fault injected: interleave A and B fragments in every legal order; fragments that are each invalid JSON but complete to valid JSON; close with incomplete JSON; stray delta after close; empty-arguments call in both buffered and streamed form.
- Prevents: argument fragments attached to the last call (llm-rosetta PR 628); signatures attached to the wrong block through positional lists (openai-agents, issue 4154); parallel streaming crossing names and arguments (Pydantic AI, issue 6759); stray arguments after completion corrupting the result (Pydantic AI, issue 5757); streamed empty arguments `""` versus buffered `"{}"` (NeoGraph audit, issue 311 item).

### 5.5 SnapshotNotAppend

- Statement: a final whole-item snapshot or a repeated usage snapshot is never added on top of already accumulated deltas. A snapshot that contradicts accumulated content is a failure. Cumulative sources are applied as set, delta sources as add.
- Exercised by: reviewed golden with hand-computed arithmetic, reference model, repeat-and-duplicate mutations of snapshot events.
- Fault injected: duplicate the final snapshot; deliver snapshot then deltas and deltas then snapshot; send a contradicting snapshot.
- Prevents: doubled text or arguments; cache and input tokens double counted when a start event and a delta event both carry usage (genai issue 272, Bifrost issues 5354 and 3451, Envoy issues 2279 and 2290); merge that overwrites instead of combining (llm-rosetta PR 771); stream builder mixing chunks (LiteLLM issue 25869).

### 5.6 UsageKnowledgeTransitions

- Statement: explicit zero is not absent. The public usage event is a full absolute snapshot, so a later snapshot can move a field from known to unknown, and known to zero. Vendor Set, Add and Invalidate are applied privately. The provider's own reported total is kept beside the derived one. Input totals include cache reads and writes, and output totals include reasoning, under the family's algebra. Partial, final, consistent and inconsistent are independent states. Overflow, wrong types and subset conflicts are reported and not hidden.
- Exercised by: hand-calculated arithmetic fixtures (for example an Anthropic case with uncached, cache-read and cache-write tokens summing to the input total; a Gemini case where thoughts are added to candidates), property generator over update sequences, reference model for transitions.
- Fault injected: usage missing entirely; zero snapshot after a positive one; conflicting subset and total; late invalidation; usage arriving after the terminal event; overflow-size values.
- Prevents: Anthropic input excluding cache (3 versus 9,818 observed in the NeoGraph audit, issue 308), Gemini candidates excluding thoughts (3 versus about 269 billed), Anthropic stream with no total reported as zero, usage fields never filled; inconsistent meaning across routes for the same model (Portkey issue 1564); negative uncached count on one route (Vercel AI SDK, issue 13902); contradictory cached-exceeds-prompt values from untranslated semantics (llm-rosetta). A known value later becoming unknown must not leave a stale count.

### 5.7 NativeRetentionForeignGate

- Statement: within one origin, signed, unsigned, empty and redacted reasoning blocks are retained whole, in order and byte-identical where the signature binds the representation, and are replayed without editing. Blocks with the same index but different type stay separate. A capsule is bound to its origin `(family, vendor, effective authority, route scope)`. Replay to a different origin is refused by default, and Drop or Demote happens only when explicitly requested. Same-origin unsigned blocks are never demoted. A vendor switch in the middle of a tool loop is refused. No foreign native value ever appears in an outbound native wire field.
- Exercised by: byte and ordered-value oracle for retention, target-origin matrix for the gate, outbound-body capture (the scripted server records what was sent), plus the live canary for actual acceptance.
- Fault injected: each block kind in buffered and streamed form; two blocks sharing an index with different types; replay to every other origin, including the same vendor through a different host; a tool loop with a vendor switch; explicit Drop and Demote requests.
- Prevents: dropped Gemini signatures causing a 400 on the second tool turn; thinking, redacted thinking, Responses reasoning items and OpenRouter reasoning details not captured (NeoGraph audit, issues 305 and 306); Anthropic thinking blocks leaking to OpenAI-compatible backends (LiteLLM, issues 31279 and 32188); forged foreign fields from "best effort" cross-provider passes (llm-rosetta); demoting an unsigned same-provider block causing a 400 (Pydantic AI, issue 7908); empty reasoning strings deleted by a sanitizer (Vercel AI SDK, issue 14071).
- Limit: synthetic capsules do not prove a vendor will accept a replay. That evidence comes only from the canary (section 9).

### 5.8 StopMeaning

- Statement: a tool call alongside a natural stop is `ToolUse`. Length, content filter, pause, context-window, refusal and the like keep their meaning and are not collapsed. A raw vendor value is kept next to the normalized kind. Unknown vendor stop values are kept raw and are not mapped to a success.
- Exercised by: consumer stop oracle (reviewed golden for mixed text plus tool turns, tool plus length, parallel tools, interrupted streams) across all assembly paths.
- Fault injected: Gemini-style `STOP` with a function call; OpenAI-compatible `stop` with `tool_calls`; `max_tokens` with a call; pause and context-window values; a blocked or malformed-call finish reason.
- Prevents: tool call reported as `end_turn` so an agent stops instead of running the tool (NeoGraph audit, issue 307 and PR 323; LiteLLM issue 21041; Bifrost issue 3638 regressing as 6123 for mixed text and tool turns); pause and context-window stops becoming "unknown", and malformed-call finish reasons becoming quiet `end_turn` (NeoGraph audit).

### 5.9 TransportProjectionParity

- Statement: one scripted logical response, expressed as buffered, SSE and (where the family supports it) WebSocket, yields identical messages, usage, stop, native carry and journal projection. Callback timing is a separate contract. Parity is required only where the replay representation is identical, because buffered and streamed assembly can differ in raw bytes while agreeing in meaning.
- Exercised by: every recorded and synthetic reply decoded through all supported transports and compared. This is the reference idea behind rig's buffered-versus-stream parity test, generalized to the final projection.
- Fault injected: the same reply with different chunking per transport; native blocks whose whitespace differs between buffered and assembled forms (parity is then asserted on the replay projection, not on raw bytes).
- Prevents: three-parser drift. WebSocket early close surfacing as a generic end-of-file error while HTTP was typed (NeoGraph audit, WS close status); streamed versus buffered empty arguments differing; duplicated reasoning-carry code in SSE and WS paths; error handling fixed in one transport only.

### 5.10 RetrySafetyBudgetDeadline

- Statement: default is one attempt. With retry opted in, in exactly one layer: a retry class (transient, after reset) and a retry safety (`NotSent`, `PossiblyAccepted`, `OutputObserved`) are separate, and both must allow it. Quota-exhausted 429 is never retried. A request body already written followed by a timeout is `PossiblyAccepted` and is not retried by default. After `OutputObserved`, no reconnect or retry, and a retry result is never appended to the same accumulator. No dispatch before a server Retry-After has elapsed or after the absolute deadline. Total attempts stay within the shared budget. Cancellation ends a read or a backoff wait.
- Exercised by: scripted server plus a virtual clock and an injected RNG, attempt-evidence oracle, counters of dispatches.
- Fault injected: each failure shape at each point (before connect, after body write, mid-stream after output, quota body, rate-limit with Retry-After in seconds and as HTTP date), an exhausted budget, a deadline that falls inside the Retry-After wait, cancel during backoff, and fault removal followed by a recovery check.
- Prevents: non-429 transient errors retried with a 30-second default, and retry after chunks reached the caller producing duplicate output (NeoGraph audit); quota exhaustion retried as a transient 429 (LiteLLM issue 32785); captured Retry-After never reaching the scheduler (Bifrost issue 6971); retries multiplied across layers (LiteLLM, Pydantic AI documentation of N by M by K). Note that a current NeoGraph test treats a cut stream without a callback as retry-safe. That expectation is not migrated.

### 5.11 IntentOrError

- Statement: every declared option either reaches the wire with its intended meaning or fails before any request is sent. An undeclared or misspelled option, a reserved-path collision or an unsupported feature causes zero network requests. Explicitly set values (temperature, budgets) are never silently altered.
- Exercised by: body-sensitive capture at the scripted server (actual sent body compared with the intent), a per-option probe that changes one option at a time and diffs the wire body against a baseline in both directions with the declared-options list, and a server-side request counter (not a mock echo).
- Fault injected: each declared option toggled; one typo per option name; every reserved path; each unsupported option per descriptor.
- Prevents: undeclared per-call fields silently dropped so a typo succeeds (NeoGraph audit, issue 309); reasoning effort dropped by a built-in schema (NeoGraph audit, PR 304); temperature forced or rejected for new models and reasoning modes; same silent drop in Portkey (issue 1469) and Bifrost (issue 5764). The per-option probe follows a test in Pydantic AI.

### 5.12 OwnershipAndBounds

- Statement: the operation owns its callback state. Dropping the last external owner inside a callback, concurrent cancel and destroy, and destruction from the callback thread never cause use-after-free, deadlock, a second outcome or a callback after completion. Cancel in the destructor does not block. An explicit `join()` is the callback fence, and calling it from a callback thread is refused. Frame size, part count, tool arguments and carried-block size have limits that fail with a resource error instead of growing memory. Secrets are absent from logs, exceptions and public cassettes.
- Exercised by: real loopback HTTP, SSE and WebSocket with slow readers and slow callbacks, sanitizer builds (ASan, UBSan, and a thread sanitizer job), boundary-generated oversize corpus, marker scan (section 3).
- Fault injected: release the last owner from inside a delivery callback; cancel racing completion; destruction during backoff; frames one byte over each limit; a planted secret marker.
- Prevents: a reader task leaked when the consumer dropped the stream (async-openai issue 576); error bodies leaking account or user identifiers into exception messages and logs (NeoGraph audit, OpenRouter error body). The lifetime and limit class is derived from the design, not from an audit row, and is marked as inference.

### 5.13 JournalVersionAndCanonicalOrder

- Statement: the consumer journal identity is `provider-completion/v2`. A version mismatch is rejected before dispatch. The v2 identity includes the ordered messages and parts with vendor ids and phases, stop (raw and normalized), nullable usage with provenance, exact native bytes with origin and representation version, and continuation and artifact identity. It changes when usage moves between unknown and zero, when native bytes or origin change, or when continuation changes. It does not change with chunk partition, local ids, timestamps, request id, transport or loss diagnostics. Local ids are canonically remapped, and ordering is by semantic order key, not arrival.
- Exercised by: pinned bytes-and-hash goldens owned by the consumer, transitions over each included field, partition and local-id perturbation of each excluded field.
- Fault injected: change each included field singly and expect a different identity; change each excluded field and expect the same. A v1 journal presented to a v2 reader.
- Prevents: the v1 digest covers message, stop reason and three usage counters only, and omits cached tokens, reasoning tokens and artifacts (measured in the current implementation), so changes in them leave identity unchanged. Stored-history versioning without a plan was costly in another framework (LangChain output-version migration). Raw-byte hashes are not semantic identity. Parity is asserted only for fixtures with the same replay representation.

### 5.14 InstallAndDependencyDAG

- Statement: a clean external consumer compiles, links and sends a loopback request against the installed tree using only the installed headers. The installed headers (four to six) include no yyjson, Asio, OpenSSL or HTTP-library header. Private object targets obey the include direction: the core never includes a codec or transport, codecs never include transport, transport never includes codec or client. There is one installed target.
- Exercised by: an install-tree consumer build in CI, a standalone compile of each public header, and include-direction checks from the compiler's dependency output and the CMake target graph (linking a dependency as PRIVATE alone does not stop a stray include).
- Fault injected: a planted forbidden include in a public header, a planted reverse include between private targets, and a planted install of a private header. Each must fail the gate.
- Prevents: third-party types in the public surface (the current implementation exposes its JSON library); installed internals becoming de facto API (breaking-change studies). This property is about packaging and includes no vendor semantics.

## 6. Reference state machine

A small test-only implementation, separate from production tables and helpers.

- Global states: `Receiving`, `TerminalObserved`, `Failed`, `Cancelled`. Terminal observation is not the end: the family may allow a usage trailer. Framing end, semantic completion and delivery end are separate facts.
- Per tool call: `NotSeen`, `Open`, `Closed`. Only `Closed` can reach dispatch.
- Checks generated sequences, including legal interleavings and near-legal sequences that break exactly one rule (missing start, duplicate id, wrong block index, delta after close, early terminal, EOF, error after text).
- A timeout alone never proves that the server is quiet forever. Local error contracts use a fake clock with a scripted EOF.

## 7. Generators and fuzzing

Three layers, each with its own grammar:

1. Byte layer: incremental UTF-8 and SSE framing, valid and near-valid bytes.
2. Family frame layer: known, unknown and corrupt frames per family.
3. Event sequence layer: legal and one-rule-broken sequences into the accumulator.

Sanitizer and time and size limits are crash oracles. The properties above are semantic oracles. Not crashing is never counted as correct. The corpus unit is a sequence, with assembler-state coverage collected. Failing seeds only are added to the corpus. Shrinkers keep tool ids and sequence dependencies.

## 8. Metamorphic relations allowed

Allowed, because meaning is provably preserved for the fixture: re-partitioning bytes, inserting SSE comment lines, changing line endings among CR, LF and CRLF, adding a leading BOM at stream start, and interleaving calls while preserving each call's internal order.

Not allowed: splitting inside a JSON string by newline (multi-line `data` joins with LF, so this changes meaning), reordering reasoning blocks, reformatting an opaque signed value, or canonicalizing opaque bytes.

## 9. Live canary

Purpose: catch what recorded fixtures cannot: real vendor drift and real acceptance of a replay.

### 9.1 Design

- One cell per family, vendor host and supported transport, with a representative model.
- Scenario: a same-origin two-turn tool loop. Turn 1 asks for a tool call with reasoning enabled where the family returns signed or encrypted reasoning. The test captures exactly what was returned and replays it unchanged in turn 2 together with a tool result. Variants where available: unsigned, redacted and empty reasoning blocks.
- Assertions are structural and never depend on prose: terminal present; stop is `ToolUse` for turn 1; call ids correlate; reasoning blocks retained byte-identical; turn 2 accepted with no signature or binding error; the usage arithmetic holds numerically under the family's algebra; raw vendor usage recorded.
- Foreign-origin refusal and Drop and Demote need no live call. They are asserted client-side on the outbound body.
- A separate restricted store holds the real opaque bytes for the duration of a run. The public report contains only the result contract.

### 9.2 Cadence and budget

- Daily, per family, a short text, stream and tool-return canary on a representative cell.
- Weekly rotation: reasoning replay, cache behaviour, Responses WebSocket, Interactions continuation, optional knobs.
- Call and token caps are explicit. A run without credentials is marked `not run` and is never shown as green. Vendor outages do not fail deterministic CI, but a cell whose canary failed is not released as verified.
- Each cell's last success date and descriptor verification date go into the release manifest.

### 9.3 Drift detection by behavioural fingerprint

A fingerprint is a structural summary, not sampled prose: the set of event type tags seen, the field types per tag, stop and usage inclusion relations, presence of a replay rejection, and capability rejections, keyed by vendor, family, API version, model and date.

- A new tag, a changed known-field type, a changed stop or usage relation, or a replay rejection opens a review artifact.
- Recorded canary traffic is kept apart from goldens. It is used only to review the drift. It is never the contract and never overwrites a golden. Promotion to a fixture goes through normal review and scrub.
- Changes in generated wording are recorded but are not a codec regression.
- Statistical monitoring of model behaviour (repeated fixed prompts with a distribution test) is out of the library. It may exist as an external opt-in operations tool. The library never sends hidden billable probes, and opaque reasoning is never probed.

## 10. Running the suite against the current NeoGraph implementation

The same fixture corpus runs against the current implementation as a migration gate, through a thin target adapter built on its injectable transport and test-access seams. The adapter feeds the scripted schedule, captures outbound requests and projects the result into the fixture's expected shape.

Rules:

- Outcomes are `pass`, `expected-fail`, `unsupported` or `not-applicable`. An expected failure is a tracked entry that names the audited defect class. It must flip to pass when fixed. If an expected-fail unexpectedly passes, or a previously passing cell fails, the gate fails.
- Properties that depend on the new design (origin-bound capsules, installed-header checks, journal v2) are `unsupported` or `not-applicable` for the old implementation. They are reported as such, never as pass.
- The old-versus-new comparison is a defect-finding aid. The expected value is from the reviewed golden, not from the old output. Differences need an accepted-difference record with a named approver.
- Existing tests are reused only when their expectation matches consumer-visible meaning. Expectations that encode old defects are not migrated. Examples: a stream cut without a terminal event treated as success, and a cut stream without a callback treated as retry-safe. Incidental formatting or internal helper call order is not migrated either.
- The old journal identity `provider-completion/v1` keeps its original verification. New dispatches go through the v2 version gate, and mismatches start a new run or fork.
- Outputs of this gate: per property and family the count of pass, expected-fail and unsupported, plus the list of accepted differences.

## 11. CI gates

Pull request (deterministic, no credentials):

1. Descriptor strict load: unknown keys, duplicate keys and reserved paths are errors. The generated schema and the runtime loader accept the same documents.
2. Fixture replay: all fixtures of changed families first, then the whole small corpus. Body-sensitive matching and unused-interaction checks on.
3. Metamorphic and property suites with fixed seeds, fault-fired assertions and mutant checks (section 5).
4. Loopback smoke per advertised transport: fragmentation, reset, slow reader, cancel during backoff.
5. Sanitizer job (ASan and UBSan, plus a thread sanitizer job for ownership tests).
6. Public headers standalone compile, include-direction and target-graph checks, install-tree external consumer build.
7. Secret scan of fixtures, logs and test output, and the marker test.
8. Review rules: a pull request changing both a captured wire and its expected projection requires a second reviewer. Generated support table checked against evidence.

Scheduled:

- Byte-framer fuzz and valid or near-valid event-sequence fuzz. Failing seeds are added.
- Live canary (section 9) and drift review artifacts. Weekly rotation as described.
- Migration-gate run against the current implementation while it still exists.

Semantic release notes are required for any change to stop, usage, retry or replay meaning, even if labelled a bug fix, with the fixture and journal-identity impact reviewed.

## 12. Release criteria

The first release ships only when all of the following hold:

1. All 14 properties pass on every cell advertised as `Supported`, with fault-fired assertions green and mutants failing. No skipped cell is counted as supported.
2. Loopback smoke passes for every advertised transport.
3. A recent live same-origin tool-turn canary has succeeded in every required cell, or that cell is explicitly listed as `Unverified` and excluded from support claims. The maximum acceptable age is fixed before the first release and is not set here.
4. The consumer's journal v2 scenario passes: a real tool loop through the library with continuation, native identity, and the version gate, observed rather than compiled.
5. The migration gate report has no unexplained difference, no expected-fail that unexpectedly passed, and every accepted difference has an approver.
6. The install-tree consumer builds, and no forbidden include exists in installed headers.
7. The support table, release manifest (descriptor verification dates, last canary successes) and semantic release notes are generated and reviewed.
8. Known gaps are listed in the release notes. Nothing untested is described as supported.

## 13. Open decisions that touch conformance

These are undecided. This plan works with either option unless noted.

- D1, transport backend (a private Asio with OpenSSL stack, already used by NeoGraph, or libcurl with platform TLS as the single transport). Evidence so far: no measured comparison. The scripted loopback suite and the shutdown and cancellation scenarios are backend-independent, so both candidates can be run through the same suite before choosing. Transport behaviour is exercised only through the loopback seam.
- D2, scope of non-chat features (long-running operations, image endpoints, the OpenRouter decisions endpoint). Until decided, no conformance cell exists for them and none may be advertised as supported.
- D3, thresholds that justify the async-native core. Proposed acceptance numbers (admission delay, cancellation latency, thread and memory budgets) exist only as targets, not measurements, and NeoGraph's target concurrency is unknown. The ownership property (5.12) and the loopback slow-reader scenarios apply under either answer.
- D4, origin granularity: whether host or route scope must be part of the origin tag. Whether a signature issued by Anthropic direct is accepted through cloud-hosted or gateway routes is unverified. The canary can collect this evidence per route, and property 5.7 is written to refuse by default until a verified equivalence is added. Even a successful canary would justify only the narrow equivalence class it tested.
- D5, admission rule for new descriptor rule kinds. Options seen: two independent real cases, or three families, plus full truth-table and permutation tests proving order independence. Stateful rules are excluded under every option. The property suite must include a check that every admitted rule has its truth table.

## 14. Limits of this plan

- Fixtures prove assembly and mapping against reviewed expectations, not that a vendor behaves as recorded today.
- The canary proves acceptance for the tested cells and models on the tested day only.
- Synthetic signatures prove structure and retention, never vendor acceptance.
- Properties are proposed gates. None has been run, and every number or threshold in this document is a target, not an observation.
